# Своя зона «Кэртиана» (ID 5000)

Серверная часть уже применена: `sql/world/21_zone_kertianna.sql`
(`areatable_dbc` 5000 + `worldmaparea_dbc` 5000).

Клиент без патча зону 5000 не знает. Ниже — полный путь от пустого
квадрата карты до готовой локальности с новыми спавнами.

---

## Что уже есть

| Слой | Запись | Значение |
|---|---|---|
| `areatable_dbc` | ID 5000 | Кэртиана, ContinentID 0, ExplorationLevel 60 |
| `worldmaparea_dbc` | ID 5000 | MapID 0, границы −4500…−3200 / −1600…−900 |
| Спавны | `04_spawns.sql` | пока в зоне 139 (Драконий Погост) |

Проверка:

```sql
SELECT ID, AreaName_Lang_ruRU FROM areatable_dbc WHERE ID = 5000;
SELECT ID, AreaName, MapID FROM worldmaparea_dbc WHERE ID = 5000;
```

---

## Шаг 0. Что понадобится

| Инструмент | Где | Зачем |
|---|---|---|
| **Noggit3** (3.3.5a) | скачать отдельно | правка ADT (высота, текстуры) |
| **MapConverter / Tallis** | отдельно | MPQ → папка с ADT для Noggit |
| **Taliis** | отдельно | правка WDT/ADT вручную |
| **Ladik's MPQ Editor** | `...\Russian\x64\MPQEditor.exe` | сборка `patch-4.MPQ` |
| **WDBX.Editor** | `Downloads\WDBX.Editor` | правка `AreaTable.dbc`, `WorldMapArea.dbc` |

**Важно:** саму геометрию (ADT) нельзя «написать SQL-ом». Её либо собирают
в Noggit из пустой карты, либо берут готовый кастомный патч. Всё, что ниже
сделано в файлах мода, — это серверная и DBC-часть, чтобы зона вообще
появилась в клиенте.

## Вариант A (быстрый, рекомендуемый): зона на существующей карте

Новых ADT не нужно. Зона 5000 существует как «подпись» над областью
карты 0, а NPC стоят на готовом рельефе — на пустом участке за
Драконьим Погостом.

1. Клиентский патч: `AreaTable.dbc` + `WorldMapArea.dbc` (шаг 2 и 3 ниже).
2. Спавны: перенести координаты из `04_spawns.sql` в область зоны.
3. Всё. Рельеф — стандартный WotLK.

Ограничение: «своей» земли нет, зона — это только имя и карта.

---

## Вариант B (полноценный): своя карта через Noggit

### B1. Пустая карта

1. Запустите **Noggit3**.
2. `Create map` → имя `Kertianna`, размер по умолчанию (например 32×32 ADT).
3. Сохраните — появится папка `Kertianna/` с `Kertianna.wdt` и `.adt`.

> Map ID для сервера: **1000** (свободен; карта 0 — Восточные королевства,
> 1 — Калимдор, 530 — Запределье, 571 — Нордскол).

### B2. Рельеф

В Noggit:

- инструмент **Raise/Lower** — поднимаете остров/полуостров;
- **Texture** — травяные текстуры (`Tileset\Expansion01\...`);
- **Water** — вода по краям, уровень 0.0 по умолчанию.

Полезно: сделайте 3–4 ровные площадки под лагеря (Талиг, Дриксен, Архив).

### B3. WMO и объекты (необязательно)

- Ставьте готовые WMO (`World\wmo\...`) как здания Архива;
- `Object → Import` → `.wmo` из существующих наборов;
- Расставьте заборы, костры, палатки.

### B4. Экспорт карты

1. В Noggit `File → Save` — ADT/WDT пишутся в папку карты.
2. Через **Taliis/MPQ Editor** создайте структуру:

```
World\Maps\Kertianna\Kertianna.wdt
World\Maps\Kertianna\Kertianna_00_00.adt
...
```

3. В `MPQEditor`: создать `Data\patch-4.MPQ`, внутри — эта структура.
4. Отдельно (клиентская карта мира) — `Interface\WorldMap\Kertianna1.blp`
   и `Interface\WorldMap\Kertianna2.blp` (если хотите мини-карту).

### B5. WorldMapArea под свою карту

После B1 поменяйте в `21_zone_kertianna.sql`:

```sql
UPDATE worldmaparea_dbc SET MapID = 1000 WHERE ID = 5000;
```

Границы (`LocLeft/LocRight/LocTop/LocBottom`) считаются так:

```
LocLeft  = -533.333 * (X_adt)
LocRight = -533.333 * (X_adt + 1)
LocTop   = -533.333 * (Y_adt)
LocBottom= -533.333 * (Y_adt + 1)
```

где `X_adt`, `Y_adt` — индексы ADT в файлах (`Kertianna_XX_YY.adt`).

## Шаг 2. AreaTable.dbc (клиент)

WDBX.Editor → `locale-ruRU.MPQ` → `DBFilesClient\AreaTable.dbc` → Export.

Скопируйте строку **139** (Драконий Погост), вставьте в конец:

| Поле | Значение |
|---|---|
| `ID` | `5000` |
| `ContinentID` | `0` (или `1000` для варианта B) |
| `ParentAreaID` | `0` |
| `AreaBit` | **свободный бит** (см. ниже) |
| `Flags` | скопировать у 139 |
| `ZoneMusic`, `AmbienceID` | скопировать у 139 или подобрать |
| `ExplorationLevel` | `60` |
| `AreaName_*` | `Kertianna` / `Кэртиана` |

**AreaBit** — это «бит открытия» в `Player.dbc`/квестах. Занятые биты
смотрите командой:

```sql
SELECT MAX(AreaBit) FROM areatable_dbc;
```

Берите следующий свободный (обычно 1400–1500). Если взять занятый —
зона начнёт открываться вместе с чужой.

## Шаг 3. WorldMapArea.dbc (клиент)

Добавьте строку:

| Поле | Значение |
|---|---|
| `ID` | `5000` |
| `MapID` | `0` (или `1000`) |
| `AreaID` | `5000` |
| `AreaName` | `Kertianna` |
| `LocLeft` / `LocRight` | границы X |
| `LocTop` / `LocBottom` | границы Y |
| `DisplayMapID` | `0` |
| `ParentWorldMapID` | `0` |

> `DisplayMapID` — картинка карты. `0` = без картинки (просто подпись).

## Шаг 4. Спавны в новой зоне

После того как карта работает, скопируйте `sql/world/22_spawns_zone.sql`
(заготовка, применяется отдельно) и подставьте свои координаты с `.gps`.

Схема:

```sql
UPDATE `creature` SET `map` = 1000, `zoneId` = 5000, `areaId` = 5000
 WHERE `guid` BETWEEN 910000 AND 910199;
```

> Пока карта 1000 не создана, **не применяйте** это — NPC провалятся
> в пустоту. По умолчанию они в зоне 139 и работают.

## Проверка

1. `Cache\WDB` удалить.
2. Запустить клиент → `Ctrl+M` (карта мира) → должна быть подпись
   **Кэртиана**.
3. `.gps` в зоне должен показать `Zone: Кэртиана`.
4. `.go creature 910000` — NPC на месте.

| Симптом | Причина |
|---|---|
| Подписи нет на карте | `WorldMapArea.dbc` не попал в `patch-4.MPQ` |
| `Zone: Unknown` | `AreaTable.dbc` не подхвачен |
| Пустая земля, провал | ADT не в MPQ или MapID не совпадает с WDT |
| Зона открывается сразу везде | занятый `AreaBit` |
